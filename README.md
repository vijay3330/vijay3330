## 💡 My Testing Philosophy

> *"Quality is not the QA team's job alone — it's everyone's responsibility. My job is to make that easy."*

**Shift-left mindset** — I get involved at the requirement stage, review user stories for testability, and surface ambiguities before a single line of code is written. Finding a bug in a requirement costs zero. Finding it in production costs a lot.

**Tests should be readable** — Automation code is production code. I write test suites that a developer, PM, or new joiner can understand without a walkthrough. Clear naming, minimal magic, and good documentation.

**Manual + automation — not either/or** — Not every test should be automated, and not every bug can be found by a script. I use automation to cover regression and repetitive checks so I can spend manual testing time where it matters: edge cases, UX flows, and exploratory sessions.

**CI/CD integration is non-negotiable** — Tests that only run locally aren't reliable. I integrate suites into pipelines so the team gets fast feedback on every merge.
